# 동아리 CTF 연결 계획

2026-11-16 작성. 아직 만들지 않았고, 정한 방향과 단계별 할 일만 적었습니다.

## 1. 결정

게임은 **CTF로 들어가는 입구**만 맡습니다. 문제를 보여 주고, 문제 서버를 띄우고, 플래그를 채점하고, 점수를 매기는 일은 동아리에 이미 있는 Nimda CTF 시스템이 합니다.

- 마을의 CTF 건물에 들어가 문(또는 단말기) 앞에서 E를 누르면 그 문제의 CTF 페이지가 열립니다.
- 플래그 제출과 채점은 그 페이지에서 이루어집니다. 게임 서버는 플래그도, 문제 내용도 갖지 않습니다.

그래서 처음에 만들어 두었던 `ctf-server/`(server-core 위에 CTF 모듈을 올리는 C++ 서버)는 지웠습니다. 채점, 문제 서버, 로그인을 C++로 다시 만들 이유가 없습니다. 모듈 예시는 `server-core/examples/hello/`로 옮겼습니다.

ctf-server 같은 별도 서버가 다시 필요해지는 경우는 하나뿐입니다. **게임 자체가 문제인 경우**, 예를 들어 "게임 메시지를 조작해 잠긴 방에 들어가면 플래그가 나온다" 같은 문제를 낼 때입니다. 그때는 운영 중인 게임과 섞지 말고 `server-core/examples/hello/`를 복사해 따로 띄웁니다.

## 2. 역할 나누기

| 하는 일 | 맡는 곳 |
|---|---|
| 로그인, 팀, 문제 목록, 플래그 채점, 점수판 | Nimda 웹 백엔드 (CTF 사이트의 `/api/*`, nimda.kr과 로그인 쿠키를 함께 씀) |
| 웹·포너블 문제의 컨테이너를 띄우고 회수, 첨부파일 내려받기 링크 | Nimda CTF 문제 서버 (웹 백엔드하고만 주고받고, 사용자가 누구인지 모름) |
| 문제 화면: 설명, 인스턴스 시작, 플래그 제출 | Nimda CTF 프론트엔드 (`https://ctf.nimda.kr/challenges/<문제 코드>`) |
| 마을, CTF 건물, 문 → 문제 코드 연결, 페이지 열기 | **이 게임** |

## 3. 1단계: 문을 누르면 CTF 페이지를 새 탭으로 연다

**난이도: 쉬움, 반나절~1일.** Nimda 쪽 코드는 바꾸지 않습니다.

### 만들 것

- **CTF 건물**: 마을에 건물 하나를 짓습니다 (`server/src/game/town.cpp`의 `addPlace`, 집을 더할 때와 같은 방법). 안에는 문제마다 문이나 단말기를 놓습니다.
- **문과 문제 코드의 표**: 데이터 폴더의 `ctf.list`에 둡니다. 문제가 바뀌어도 서버를 다시 빌드하지 않고, 파일을 고쳐 서버만 다시 켜면 됩니다.

  ```
  # 한 줄에 "<문 번호>\t<문제 코드>\t<문 위에 띄울 이름>"
  1	web-login	로그인 우회
  2	pwn-echo	에코 서버
  ```

- **서버**: 입장할 때 보내는 지도 정보에 문 위치와 문제 코드를 함께 보냅니다. 플래그나 정답은 보내지 않습니다. 문제 코드는 공개된 값입니다.
- **클라이언트**: 문 앞에서 E를 누르면 `https://ctf.nimda.kr/challenges/<문제 코드>`를 새 탭으로 엽니다.

### 주의할 점

- **팝업 차단**: 브라우저는 키를 누른 그 순간에 연 창만 허락합니다. 서버에 물어보고 답이 온 뒤에 열면 막힙니다. 그래서 문과 코드의 표를 미리 받아 두었다가 키를 누르는 순간 바로 엽니다.
- **로그인**: CTF 페이지가 알아서 합니다. 로그인하지 않았으면 그 페이지의 로그인 화면으로 갑니다.
- 게임은 누가 어떤 문제를 풀었는지 모릅니다. 그래서 "푼 문에 불이 켜진다" 같은 표시는 3단계에서 합니다.

### 테스트

- 문 앞에서 E를 누르면 문제 코드에 맞는 주소로 새 탭이 열린다.
- 문에서 멀리 있으면 열리지 않는다.
- `ctf.list`를 고치고 서버를 다시 켜면 바뀐 코드가 반영된다.
- 게임 서버가 보내는 메시지에 문제 코드 말고 다른 값(플래그 등)이 없다.

## 4. 2단계: 게임 화면 안의 창(iframe)으로 띄우기 — 하지 않는다

CTF 페이지 자체는 iframe에 넣을 수 있습니다. 하지만 게임 주소(`mmo-rouge.vercel.app`, `game.nyangki.com`)와 CTF 사이트가 다른 사이트라서 iframe 안에서는 로그인 쿠키가 서드파티 쿠키가 됩니다. Safari와 최신 Chrome에서는 로그인이 유지되지 않을 가능성이 커서 새 탭이 더 안전합니다. 게임을 nimda.kr 아래로 옮기면(3단계) 다시 생각해 볼 수 있습니다.

## 5. 3단계: Nimda 계정으로 게임 로그인, 푼 문제를 게임에 표시

**난이도: 어려움, 3~5일 + 동아리 백엔드 담당과 조율.** 1단계를 써 본 뒤에 필요하면 합니다.

### 전제: 게임을 nimda.kr 아래로 옮긴다

예: 화면 `town.nimda.kr`, 게임 서버 `town-ws.nimda.kr`. 그러면 nimda.kr의 로그인 쿠키(`Domain=.nimda.kr`)가 게임 서버의 WebSocket 연결에도 함께 옵니다.

- DNS와 인증서를 동아리 쪽에서 설정해 줘야 합니다.
- 로그인 쿠키가 정말 `Domain=.nimda.kr`로 발급되는지, `SameSite` 값이 무엇인지 확인해야 합니다.

### 흐름

```
브라우저 ── WebSocket 연결 (nimda.kr 쿠키가 따라옴) ──▶ 게임 서버
게임 서버 ── 그 쿠키로 /api/auth/me ──▶ Nimda 웹 백엔드 ──▶ 닉네임
게임 서버: 그 닉네임의 게임 계정으로 입장 (게임 비밀번호 없이)
게임 서버 ── 푼 문제 목록 요청 ──▶ Nimda 웹 백엔드 ──▶ 문 표시에 반영
```

### 게임 서버에서 할 일

- 접속할 때(HTTP 업그레이드 요청) 들어온 `Cookie` 헤더를 읽어 둡니다. 지금은 읽지 않습니다.
- 웹 백엔드에 HTTP 요청을 보내야 합니다. 지금 서버에는 이 기능이 없어서 libcurl 같은 라이브러리를 더합니다.
- 20Hz 게임 루프가 멈추지 않도록 요청은 따로 도는 스레드에서 보냅니다. 시간 제한을 두고, 백엔드가 응답하지 않으면 지금처럼 게임 계정으로 로그인하게 합니다.
- 받은 쿠키는 확인에만 쓰고 저장하거나 로그에 남기지 않습니다.

### Nimda 쪽에 필요한 것

- "이 사용자(또는 팀)가 푼 문제 코드 목록"을 돌려주는 API. 지금은 없는 것으로 보입니다.
- 게임 서버가 서버끼리 부를 때 쓸 주소. 가능하면 내부망 주소로 합니다.

### 도메인을 옮길 수 없을 때

웹 백엔드가 짧게 유효한 서명 토큰을 발급하고, CTF 페이지에서 "게임으로 가기"를 누르면 그 토큰을 붙여 게임으로 보냅니다. 게임 서버는 그 토큰을 백엔드에 확인합니다. 이 방법은 Nimda 쪽에 만들 것이 더 많습니다.

### 이 단계에서도 바뀌지 않는 것

채점은 계속 Nimda 웹 백엔드가 합니다. 게임은 결과를 받아 보여 주기만 해서, 게임 서버가 뚫려도 플래그나 점수를 바꿀 수 없습니다.

## 6. 정해야 할 것

- CTF 건물을 마을 어디에 둘지, 행사 기간에만 열지.
- 어떤 문제를 문으로 놓을지 (`ctf.list`의 내용). 대회마다 바뀌니 누가 고칠지.
- 3단계를 할지: nimda.kr 하위 도메인을 쓸 수 있는지, 백엔드 담당이 "푼 문제 목록" API를 만들어 줄 수 있는지.

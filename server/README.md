# Mini MMO 서버의 뼈대

이 문서는 Mini MMO 게임 서버에서 **꼭 필요한 부분만** 설명합니다. 하우징, 농장, 미니게임, 극장 같은 콘텐츠는 빼고, "로그인해서 마을에 들어가 걸어 다니고 서로가 보인다"를 만드는 네 가지만 다룹니다. 연결, 로그인과 입장, 월드와 이동, 보내기입니다.

먼저 전체 그림입니다. 서버는 프로그램 하나이고, 모든 플레이어가 그 프로그램의 메모리에 있는 월드 하나를 함께 씁니다. 서버는 1초에 20번(20Hz) 월드를 한 칸씩 진행시키는데, 이 한 칸을 **틱(tick)**이라고 부릅니다. 플레이어의 브라우저는 "어느 키를 눌렀다" 같은 입력만 보내고, 캐릭터가 실제로 어디에 있는지는 서버가 정합니다. 그래서 누가 브라우저를 조작해도 벽을 뚫거나 순간이동할 수 없습니다.

화면에 캐릭터를 그리는 일은 서버가 하지 않습니다. 서버는 위치를 계산해서 보내기만 하고, 그림은 브라우저(`client/core/render.js`)가 그립니다.

## 1. 연결

브라우저와 서버는 **WebSocket**으로 연결됩니다. 보통 웹페이지는 요청을 보내고 응답을 받으면 연결이 끝나지만, WebSocket은 연결을 계속 열어 두고 양쪽이 언제든 메시지를 보낼 수 있습니다. 실시간 게임에는 이 방식이 필요합니다.

이 일은 `base/ws_server.*`가 맡습니다. 외부 라이브러리 없이 운영체제의 소켓 기능만으로 직접 만들었습니다. 여러 브라우저의 연결을 한 스레드에서 번갈아 살피고(`poll`), 메시지가 오면 게임 쪽(`Game::onMessage`)에 넘기며, 연결이 끊기면 그것도 알립니다(`Game::onClose`). 연결마다 번호(`ConnId`)가 붙고, 게임 쪽은 이 번호로 누구에게 보낼지를 정합니다. WebSocket 연결을 처음 맺을 때 필요한 계산은 `base/sha1.hpp`에 있습니다.

이 연결 부분은 게임 내용을 전혀 모릅니다. 메시지가 채팅인지 이동인지 신경 쓰지 않고, 글자를 받고 넘기는 일만 합니다.

서버의 심장은 `main.cpp`의 루프입니다. 이 루프는 다음 틱 시각이 될 때까지 네트워크 메시지를 처리하다가, 시각이 되면 `game.tick()`을 불러 월드를 1/20초만큼 진행시키고, 다시 메시지를 처리하는 일을 반복합니다. 메시지 처리와 게임 진행이 같은 스레드에서 차례로 일어나므로, 두 일이 동시에 같은 데이터를 건드리는 문제가 생기지 않습니다.

## 2. 로그인과 입장

연결된 브라우저는 먼저 로그인해야 합니다. 이 과정은 `core/session.cpp`에 있고, 연결은 세 단계를 거칩니다. 처음에는 아무것도 아닌 연결이고, 로그인하면 계정이 붙은 연결이 되고, 캐릭터를 정해 입장하면 월드 안의 플레이어가 됩니다. 입장하기 전에는 로그인과 입장 메시지 말고는 모두 무시합니다.

**로그인**(`login`)은 아이디와 비밀번호를 받습니다. 처음 보는 아이디면 그 자리에서 가입시킵니다. 비밀번호는 원문을 저장하지 않고, 되돌릴 수 없는 방식(PBKDF2)으로 60만 번 섞은 결과만 저장합니다. 이 계산은 일부러 느리게 만든 것이라 메인 루프에서 하면 게임이 멈춥니다. 그래서 별도의 작업 스레드(`base/worker.hpp`)에 맡기고, 끝나면 결과만 메인 루프로 돌려받습니다.

로그인에 성공하면 서버는 **이어 들어오기 표**를 줍니다. 30일 동안 쓸 수 있는 서명된 문자열로, 연결이 잠깐 끊기거나 서버가 다시 켜져도 브라우저는 이 표(`resume`)로 비밀번호 없이 다시 들어옵니다.

**입장**(`join`)은 캐릭터의 색, 팔·다리 모양, 이름을 받아 월드에 넣는 단계입니다. 이때 `placePlayer`가 세울 자리를 정합니다. 계정에 저장된 마지막 위치가 아직 설 수 있는 곳이면 거기에 세우고, 처음 오는 사람이거나 그 자리가 막혔으면 마을 광장 근처의 빈 곳에 세웁니다. 입장한 사람에게는 월드 지도와 자기 위치를 보내고, 모두에게 "○○님이 입장했습니다"를 알립니다.

계정은 `core/accounts.*`가 관리합니다. 계정마다 텍스트 파일이 하나씩 있고, 서버를 켤 때 전부 메모리로 읽어 둡니다. 플레이어의 위치와 모양은 퇴장할 때, 서버를 끌 때, 그리고 접속 중에는 20초마다 파일에 저장합니다(`syncAccount`). 파일은 임시 파일에 먼저 쓰고 이름을 바꾸는 방식이라, 쓰는 도중에 서버가 죽어도 이전 파일이 온전히 남습니다.

## 3. 월드와 이동

월드의 모양은 `core/world.*`에 있습니다. 강, 다리, 건물, 고정된 가구, 그리고 지나갈 수 없는 영역(충돌 영역)이 모두 여기서 정해집니다. 서버를 켤 때 한 번 만들어지고 바뀌지 않습니다.

월드는 **구역(zone)**으로 나뉩니다. 0번 구역이 마을이고, 1번부터는 건물 안입니다. 구역은 서로 완전히 분리된 공간이라, 같은 구역에 있는 사람끼리만 서로 보입니다. 건물 문 앞에서 E를 누르면 `tryDoor`가 가까운 문을 찾고, `moveToZone`이 플레이어를 그 문이 이어진 구역으로 옮깁니다.

캐릭터가 움직이는 과정은 이렇습니다. 플레이어가 방향키를 누르거나 떼면, 브라우저는 지금 눌린 방향들을 숫자 하나로 묶어 `in` 메시지로 보냅니다(위 1, 아래 2, 왼쪽 4, 오른쪽 8을 더한 값). 서버는 이 값을 기억만 해 둡니다(`setInput`). 그리고 틱마다 그 방향으로 1/20초 동안 갈 거리(초당 220px)만큼 캐릭터를 옮깁니다. 대각선으로 갈 때는 더 빨라지지 않도록 보정합니다. 위치를 보내는 대신 누르고 있는 방향만 알리는 방식이라, 메시지가 적고 브라우저가 속도를 조작할 수도 없습니다.

옮기기 전에는 `World::move`가 충돌을 확인합니다. 가려는 곳이 강물이거나 건물·가구의 충돌 영역 안이면 그쪽으로는 가지 않습니다. 다만 가로와 세로를 따로 확인해서, 벽에 비스듬히 부딪히면 벽을 따라 미끄러지듯 움직입니다.

입장할 때 서버는 이 월드 전체를 지도(`map` 메시지)로 브라우저에 보냅니다. 브라우저는 같은 지도와 같은 충돌 규칙으로 내 캐릭터를 먼저 움직여 보여 주고(예측), 서버에서 위치가 오면 어긋난 만큼 맞춥니다. 그래서 인터넷이 조금 느려도 내 캐릭터는 키를 누르는 즉시 반응합니다.

## 4. 보내기

서버는 매 틱이 끝날 때 `core/send.cpp`의 `broadcastState`로 각 구역의 모습을 그 구역 사람들에게 보냅니다. 이 `state` 메시지에는 그 구역에 있는 모든 플레이어의 번호, 위치, 몸 색, 이름이 들어 있습니다. 앉아 있는지, 누르고 있는 방향은 무엇인지 같은 값은 해당할 때만 덧붙여 메시지를 짧게 유지합니다. 브라우저는 이 메시지를 받아 다른 사람들을 그 위치에 그리고, 틱 사이는 부드럽게 이어 그립니다.

보내는 범위는 세 가지입니다. `sendToZone`은 한 구역의 사람들에게만, `sendToAll`은 접속한 모두에게 보내고, 연결 번호를 지정하면 한 사람에게만 보냅니다. 위치는 같은 구역에만 보내고, 입장·퇴장 안내(`systemMessage`)는 모두에게 보내는 식입니다.

서버가 보내는 메시지는 모두 JSON이고, `t` 값이 종류를 나타냅니다. 예를 들어 `{"t":"state", ...}`는 위치, `{"t":"zone", ...}`은 구역 이동, `{"t":"sys", ...}`는 안내 문구입니다.

## 메시지 한눈에 보기

이 네 가지만으로 돌아가는 서버가 주고받는 메시지는 이것뿐입니다.

| 방향 | 메시지 | 뜻 |
|---|---|---|
| 브라우저 → 서버 | `login <아이디> <비밀번호>` | 로그인 (없는 아이디면 가입) |
| 브라우저 → 서버 | `resume <표>` | 이어 들어오기 표로 다시 로그인 |
| 브라우저 → 서버 | `join <색> <팔> <다리> <팔다리색> <이름>` | 캐릭터를 정하고 입장 |
| 브라우저 → 서버 | `in <방향>` | 지금 누르고 있는 방향 |
| 브라우저 → 서버 | `use door` | 문으로 들어가거나 나가기 |
| 서버 → 브라우저 | `auth` | 로그인 결과 (성공하면 이어 들어오기 표 포함) |
| 서버 → 브라우저 | `welcome` | 입장 승인, 내 연결 번호 |
| 서버 → 브라우저 | `map` | 월드 지도 (입장할 때 한 번) |
| 서버 → 브라우저 | `zone` | 내가 있는 구역과 위치가 바뀜 |
| 서버 → 브라우저 | `state` | 같은 구역 사람들의 위치 (매 틱) |
| 서버 → 브라우저 | `sys` | 안내 문구 |

## 실행

```bash
cd server
make run        # = ./mmo_server 8080 ../client ./data
```

브라우저에서 http://localhost:8080 에 접속합니다. 창을 두 개 띄워 서로 다른 아이디로 들어가면 서로 보입니다.
